# Helper API

Omarchy's shell starts the helper and talks to it over its stdin and stdout with [JSON-RPC 2.0](https://www.jsonrpc.org/specification), one JSON object per line. The helper exits when stdin closes or on SIGTERM.

```sh
oma-messenger-service [--data-dir DIR] [--db FILE] [--version]
```

The protocol version is `3`.

## Methods

| Method | Params | Result |
| --- | --- | --- |
| `hello` | | `{protocol, version, unreadTotal, unreadByService, services}`; `unreadByService` is `{whatsapp: N, telegram: N, …}`, omitted entries meaning zero; `services` is `[{id, name}]`, the messaging services available to add an account for |
| `accounts.list` | | `[Account]`, each with an added `attachmentLimit`: the largest file its connector currently accepts to send, in bytes - Telegram's 2 GiB cap, doubled to 4 GiB for a Premium account, or WhatsApp's 2 GiB document cap (see `media.attach`'s own, kind-specific figures) |
| `accounts.add` | `{service, apiId, apiHash, options}` | `Account`. `apiId` and `apiHash` are Telegram's own API keys, kept for compatibility; `options` is the general form, a map of a provider's own setup values (Telegram reads the same two keys from it as `apiId`/`apiHash` strings). Without either, the account uses OmaMessenger's own keys |
| `accounts.remove` | `{accountId}` | `{}`; signs out and deletes the account's session, credentials and messages |
| `accounts.setAlias` | `{accountId, alias}` | `Account`; saves the display name the user chose for the account, such as "Personal WhatsApp", shown instead of its plain name wherever it is identified. An empty `alias` clears it, falling back to the plain name again |
| `auth.submit` | `{accountId, step, value}` | `{}`; answers an `auth.step`: `phone`, `code` or `password` |
| `contacts.list` | `{accountId, query}` | `[Contact]` |
| `contacts.block` | `{conversationId}` | `Conversation`; blocks the contact behind a direct conversation, through the service. Fails with invalid params for a group, or a service that refuses, such as one that offers no block API at all |
| `contacts.unblock` | `{conversationId}` | `Conversation`; the reverse of `contacts.block` |
| `conversations.list` | `{query}` | `[Conversation]`, newest first; `match` holds the newest matching message, and `matchMessageId`/`matchSender` identify it and who sent it, for a caller that wants to open and highlight that exact message rather than just the conversation (the unified command palette's "Messages" section). `blocked` is set once the contact behind a direct conversation has been blocked (see `contacts.block`); always `false` for a group. `notificationSound` is `"custom"` once a conversation has its own notification sound (see `conversations.setNotificationSound`), `""` (omitted) otherwise |
| `conversations.open` | `{accountId, contactId}` | `Conversation`, created if needed |
| `conversations.markRead` | `{conversationId}` | `{}`; also the command palette's "Mark as read" |
| `conversations.markUnread` | `{conversationId}` | `Conversation`; the command palette's "Mark as unread". Local to this computer only, never reported to the service: it gives the conversation an unread count of 1, and does nothing when it already has an unread count of its own, so this can never lower a real count the service reported |
| `conversations.setMuted` | `{conversationId, muted}` | `Conversation` |
| `conversations.setNotificationSound` | `{conversationId, path}` | `Conversation`; validates path (an audio file: Ogg/Opus, MP4/M4A or a simple constant-bitrate MP3) with the same check `media.fetch` already uses for a voice note, copies it into the helper's own sound store, and gives the conversation its own notification sound, overriding whatever its service or the global default setting plays. `notificationSound` on the result (and on every other `Conversation` this conversation appears in) is `"custom"` once set, `""` otherwise; the sound's own bytes never cross the protocol - see `sounds.fetch`. Fails with invalid params for a missing file, or one that is not a format `audiosafe` accepts, naming no detail about the file itself |
| `conversations.resetNotificationSound` | `{conversationId}` | `Conversation`; the command palette's "Reset notification sound": clears a conversation's own sound back to inheriting whichever one applies at the service or global default level, and removes the file `conversations.setNotificationSound` stored for it |
| `conversations.setPinned` | `{conversationId, pinned}` | `Conversation`; `conversations.list` always orders pinned conversations first, then by `pinOrder` (see `conversations.movePin`). Pinning is local and unlimited; a service with its own limit on pinned chats (WhatsApp's own app allows three) fails with invalid params past it, but the local pin still stands |
| `conversations.movePin` | `{conversationId, direction}` | `Conversation`; moves a pinned conversation one place up or down (`direction: "up"` \| `"down"`) among the other pinned conversations, swapping places with whichever pinned neighbor is already there. A no-op at either edge of the pinned group. Fails with invalid params for a `direction` other than `"up"`/`"down"`, or not found (`-32001`) for a conversation that is not currently pinned. Local reordering only, never reported to a service: both conversations' new summaries arrive as `conversation.updated` events, this call's own result being the one named in `conversationId` |
| `conversations.setArchived` | `{conversationId, archived}` | `Conversation`; `conversations.list` still returns archived conversations, the UI hides them by default |
| `conversations.setHidden` | `{conversationId, hidden}` | `Conversation`; local to this computer only, never reported to the service. `conversations.list` still returns hidden conversations, the UI hides them by default |
| `conversations.setReminder` | `{conversationId, at}` | `Conversation`; snoozes until `at` (Unix milliseconds), or clears the reminder when `at` is `null`. Local to this computer only, never reported to the service. The helper fires it at `at`: a `conversation.updated` event (`reminderAt` now in the past) and a desktop notification, "Reminder: `<title>`" unless notifications are set to "Nothing". The reminder is not cleared automatically once due; `conversations.setReminder` with `at: null` clears it |
| `conversations.members` | `{conversationId}` | `{members}`: `[{id, name}]`, a group's current members, for the composer's @-mention picker. Empty for a direct chat or a service that does not list members |
| `conversations.reportSpam` | `{conversationId}` | `Conversation`; reports a direct conversation's contact as spam through the service when it offers a report of its own, then blocks the contact and hides the conversation from the standard list, matching what the official apps do. Fails with invalid params for a group. WhatsApp's own API has no spam report, so only the block and hide happen there; a service that fails the report itself fails the whole call rather than blocking anyway |
| `messages.list` | `{conversationId, before, limit}` | `{messages, hasMore, historyUnavailable}`, oldest first; `limit` 1–200, default 50. Past the oldest stored message it fetches older history from the service, which arrives as `message.added` too. `historyUnavailable` (omitted when false) is set when that fetch could not reach the service right now, such as a WhatsApp account whose phone never answered an on-demand request in time; the page already loaded is returned either way |
| `messages.send` | `{conversationId, text, attachment, replyTo, mentions}` | `Message`; status `failed` if the service refused it. `attachment` is optional: `{path, name}` names a file to send, with `text` as its caption (`text` may then be empty); an attachment over the conversation's own account limit is rejected (2 GB by default; see `media.attach`, which already refuses the same file earlier, at attach time). `path` should be the `path` a prior `media.attach` or `media.paste` call returned, not a raw path straight from a file picker (see `media.attach`); `name`, also optional, overrides the attachment's display name for a `path` like that, whose own base name carries an internal id rather than the name the user picked - omitted, the display name falls back to `path`'s own base name, right for a plain disk path from an older UI. `replyTo`, also optional, is the local id of a message in the same conversation this one answers; it works together with `attachment`. `mentions`, also optional, is `[{userId, name, offset, length}]`, the "@name" tokens in `text`: `offset` and `length` are in UTF-16 code units, the same unit a JavaScript string already indexes by |
| `messages.retry` | `{messageId}` | `Message`; only for failed outgoing messages. The helper also retries a failed message on its own - once its account reconnects, and otherwise on a backoff for up to a day - so this is for a retry the user asks for sooner; it always starts that backoff over |
| `messages.react` | `{messageId, emoji}` | `Message`; sets the user's reaction to `emoji`, or clears it when `emoji` is `""`. Fails with invalid params if the service does not support reactions |
| `messages.vote` | `{messageId, optionIds}` | `Message`; casts the user's vote in the message's poll, replacing any previous vote. `optionIds` names `domain.PollOption.ID` values from the poll's own `options`. Fails with invalid params for a message with no poll, a closed poll, or a service that does not support voting |
| `messages.delete` | `{conversationId, messageIds, forEveryone}` | `{}`; deletes messages for everyone, through the service, when `forEveryone` is true, or only for this account otherwise. A failed message that never reached the service is deleted locally with no connector call at all, `forEveryone` ignored, and drops its outgoing attachment, if any. Fails with invalid params if the service refuses, such as "for everyone" on a message that is not yours, or "for me" where only "for everyone" is possible. Removal arrives as `message.removed`, the same as a deletion the service reports on its own |
| `messages.edit` | `{conversationId, messageId, text}` | `Message`; changes an outgoing text message's words, updating the store at once and telling the service. Only a message you sent, with no attachment, that has already reached the service (it has a remote id) can be edited. Fails with invalid params for anything else, for an empty `text`, or if the service refuses, such as past its own time limit to edit a message; a refusal reverts the message back to its original text. The service's own later echo of a successful edit arrives as `message.updated`, same as any other |
| `messages.schedule` | `{conversationId, text, sendAt}` | `ScheduledMessage`: `{id, conversationId, text, sendAt, created}`. Queues a text-only message to send at `sendAt` (Unix milliseconds), which must be in the future; fails with invalid params for empty or over-length `text`, or a `sendAt` not in the future. Attachments are not supported in this first version. The helper sends it through the normal send path once `sendAt` comes, even if the helper was not running right at that moment (it sends anything overdue once, on its next start); a failed send is retried automatically, exactly like any other failed send, and arrives as `message.added` followed by the usual `message.updated` status changes, not as another `scheduledMessage.*` event |
| `messages.listScheduled` | `{conversationId}` | `{messages: [ScheduledMessage]}`, soonest due first. `conversationId` is optional: omitted or `""` lists every message queued anywhere, for the "Scheduled messages" command; given, only that conversation's own, for its own pending list |
| `messages.editScheduled` | `{scheduledId, text, sendAt}` | `ScheduledMessage`; changes a queued message's text and send time, validated the same way `messages.schedule` validates a new one. Not found (`-32001`) once it has already been sent or cancelled |
| `messages.cancelScheduled` | `{scheduledId}` | `{}`; removes a queued message before it sends. Not found (`-32001`) once it has already been sent |
| `messages.sendScheduledNow` | `{scheduledId}` | `Message`; sends a queued message right away instead of waiting for `sendAt`, through the normal send path, the same as a message due now. Not found (`-32001`) once it has already been sent or cancelled |
| `media.fetch` | `{messageId, auto}` | `{path, decodeAs, playable, risky}`: the message's photo, video, file, voice note or audio message. For a message you sent, its own local copy is returned at once; otherwise it is downloaded into the media cache the first time, cached under a name built from the message's own id and an extension chosen from the downloaded bytes themselves (sniffed, from a fixed allow-list; an unrecognised type gets `.bin`) for every kind but a photo or video, which always get `.jpg`/`.mp4` - never from the message's own claimed file name, which a sender fully controls (see `docs/decisions.md`). `decodeAs` is set only for a video, and only once the helper has confirmed, from the downloaded file's own bytes rather than the message's filename or `animated` flag, that it is a genuine, sanitized GIF image: `"gif"`. It is omitted for an ordinary video or any other kind; the UI must use only this field, never a message's own metadata, to decide whether to decode a video through an image component instead of a video one. `playable` is set for an ordinary video (`decodeAs` omitted), once the helper has parsed its downloaded container and stream headers in pure Go and confirmed an allowed video codec (H.264, VP9 or AV1 in MP4/MOV; VP8, VP9 or AV1 in WebM/Matroska), dimensions no larger than 1920 on either side, a duration no longer than 10 minutes, no more than a few video tracks, a sane declared sample count, and, if it carries audio, an allowed audio codec (AAC or Opus in MP4/MOV; AAC, Opus or Vorbis in WebM/Matroska); omitted (`false`) for anything that fails that check, or for a video a sender's bytes turned out to be a GIF image (`decodeAs: "gif"`, which never consults `playable` at all). The UI may load a video into its own player only when `playable` is true (or `decodeAs` is `"gif"`); otherwise it offers only to open the file in the user's own video player. `playable` is also set for a voice note or an ordinary audio message (kind `voice` or `audio`), once the helper has parsed its downloaded bytes in pure Go (see `backend/internal/audiosafe`) and confirmed a single-stream Ogg carrying Opus, an MP4/M4A carrying AAC or Opus with no video track, or a simple constant-bitrate MPEG-1 Layer III (MP3) stream, in every case within a duration of 30 minutes; omitted (`false`) for anything that fails that check, such as a free-bitrate or multiplexed-stream file. The UI may load a voice note or audio message into its own in-window player only when `playable` is true; otherwise it offers only the same gated external-open path a video or file gets. Neither a video's, a voice note's nor an audio message's `playable` is ever inferred from the message's own kind, claimed file name or mime type - only the downloaded bytes decide (see `docs/decisions.md`). `risky`, omitted (`false`) for everyday media, is `true` when the downloaded bytes are active or executable content - a web page, a vector image carrying a script, or anything this helper does not recognise at all - sniffed fresh from `path`'s own bytes every time, never the message's claimed file name or kind; the UI must ask the user to confirm before opening a file this names risky with anything but its own built-in viewers, offering "Save to Downloads" as the safe default, and must never decide this for itself. `auto`, optional and defaulting to `false`, is `true` for a fetch the UI made on its own, with no click from the user - a photo, sticker or voice note shown as a message's row comes into view, or an animated "GIF" video autoplaying - which bounds the download to a far smaller size than a deliberate fetch (`false`, including every click, the viewer opening, and a retry of something an automatic fetch already refused) is trusted with; a video never auto-fetches at all (see `ui/components/InlineVideo.qml`), only a click does. A download failure answers `-32603` with `data: {reason}`, one of `not-found`, `expired`, `download`, `decrypt`, `too-large`, `cache` or `timeout`, safe to show; the helper also logs the same category to stderr. `expired` is WhatsApp-specific: it means the CDN link had aged out and the primary phone, asked to re-upload it, confirmed the media is gone or never answered. `too-large` means the file's declared or actual size exceeded the limit that applied (the automatic cap, the larger user-requested one, or the media cache's own overall limit) |
| `media.save` | `{messageId}` | `{path}`: the message's media, fetched first if need be, then copied into the user's downloads directory. The saved name's stem is the sender's own claimed file name, sanitized (control and Unicode bidi/format characters stripped, whitespace collapsed, length capped) and shown only, never used to decide how the file is cached or opened, or a fixed fallback stem when sanitizing leaves nothing usable; its extension always comes from the downloaded bytes' own sniffed content type, never the sender's claim, with " (2)", " (3)", … added before it rather than overwriting a file already there. Fails with invalid params if the helper has no downloads directory to save into (no `HOME` when it started), or with the same reasons `media.fetch` can fail |
| `media.copy` | `{messageId}` | `{}`: the message's photo, video, file or voice note, fetched first if need be, put on the system clipboard through `wl-copy` with a fixed argv and the file given to it on stdin, under its MIME type freshly sniffed from the downloaded bytes. Fails with the same reasons `media.fetch` can fail |
| `media.paste` | | `{path, kind, width, height}`: an image copied off the clipboard into the outgoing media area, for the composer to attach to the next message sent; fails with an invalid-input error when the clipboard holds no image |
| `media.attach` | `{path, accountId}` | `{path, name, kind, width, height, size, limit}`: a file the user picked from disk, copied into the outgoing media area and, when it looks like a photo, sanitized with imagesafe's own full-size profile, the same check a downloaded or pasted photo already gets, before the composer ever shows anything built from it. `accountId` is the open conversation's account, read to look up its connector's own attachment limit; omitted (an older UI), it falls back to the 2 GB default below. `path` is the new, already-sanitized copy to send through `messages.send`'s `attachment.path`; `name` is the file's own picked name, for `attachment.name`. `kind` is `photo`, `video` or `file`, sniffed from the file's own bytes, never guessed from its name; the composer shows a decoded preview only when it is `photo`, the one kind this has actually sanitized. `width`/`height` are set only for a photo. `size` is the file's own byte count; `limit` is the cap it was checked against - Telegram: 2 GB, or 4 GB for a Premium account; WhatsApp: 16 MB for a photo or video, 2 GB for a file; 2 GB for any other service or one not yet connected - so the UI can show both without a second round trip. A file over `limit` fails outright with an invalid-input error naming the limit, the same as one that reaches `messages.send` straight from disk always has; a missing or unreadable file, or an oversized or unsafe photo, fails the same way |
| `files.pick` | `{purpose, title}` | `{path}`, omitted when the user cancelled the dialog (never an error): opens a file-choosing dialog through `xdg-desktop-portal`'s own `FileChooser`, over D-Bus, out of this process entirely - never the native, in-process GTK dialog that once crashed the whole Omarchy shell (see `docs/decisions.md`). `purpose` is `"attach"` (images, video and any other file, for the composer) or `"sound"` (audio files, for a conversation's notification sound), deciding the filters offered; `title` is shown in the dialog. Fails with an internal error carrying `data: {reason: "unavailable"}` when the portal cannot be reached or shown at all, the UI's own cue to fall back to a different, non-native file picker of its own rather than retrying the portal or falling back to the native one |
| `ui.setFocus` | `{conversationId, windowActive}` | `{}` |
| `sounds.fetch` | `{conversationId}` or `{service, path}` | `{path}`, omitted when nothing playable was found: the one method the UI calls to actually play a notification sound, once its own precedence between a conversation's, a service's and the global default sound has already picked a winner (see `ui/lib/NotificationSound.js`). `{conversationId}` resolves that conversation's own sound, stored by `conversations.setNotificationSound`; `{service, path}` ("whatsapp", "telegram" or "default", with `path` the matching manifest setting's raw value) validates and copies that file the same way, on the UI's behalf, since a manifest setting is never pre-validated the way a conversation's own sound is. Either way, the result's `path` is a local file this helper has already confirmed with `audiosafe`; an invalid or missing file resolves to no `path` at all, never an error, since a notification sound is never worth failing a request over |
| `ui.getWindowOpen` | | `{open}`: whether the window was last left open rather than deliberately closed, `false` for a fresh install. The UI reopens it once on the next start when this is `true` and the "Reopen after restart" setting is on (see `ui.setWindowOpen` and `docs/decisions.md`) |
| `ui.setWindowOpen` | `{open}` | `{}`; records whether the window is currently open. The UI calls this with `true` whenever it shows the window, and with `false` only when the user deliberately closes it - never when a shell restart or plugin reload tears the window down without asking first, which is exactly the case this exists to survive |
| `whatsNew.getSeenVersion` | | `{version}`: the version the user last saw the in-app "What's new" list for, `""` for a fresh install |
| `whatsNew.setSeenVersion` | `{version}` | `{}`; records version as seen, so the UI's one-time update hint does not show again for it |
| `settings.apply` | `{notifications, notificationPreview, notificationDetail, readReceipts, spellCheck, spellLanguage}` | `{}`; `notificationDetail` is `nameAndMessage`, `nameOnly` or `none`, and takes over from the older `notificationPreview` boolean when sent (`true` behaves as `nameAndMessage`, `false` as `nameOnly`). `readReceipts` is incognito mode when `false`: `conversations.markRead` still clears the local unread count, but `MarkRead` never reaches the connector, so the service, and any other device signed into the same account, keep showing the chat unread. `spellCheck` turns the composer's English spell check on or off (on by default); `spellLanguage` picks its dictionary: `auto` (from the locale environment, the default), `en_GB` or `en_US` |
| `helper.doctor` | | `{checks: [{name, ok, detail}]}`: the helper's own health report (version, data permissions, the database, the media cache, the outgoing media area, each account's connection, the notification service's reachability, and any recent error categories). Every field is safe to show: states and categories, never a path, a name or a token, except for a plain count where it helps, such as how many failed messages are waiting in an over-limit outgoing media area |
| `spell.check` | `{text}` | `{misspellings: [{start, end, word}]}`: the misspelled words in text, skipping URLs, `@mentions`, email addresses, numbers and `` `code spans` ``. `start` and `end` are UTF-16 code units, the same convention a mention's offset uses. Always `{misspellings: []}` while spell check is off |
| `spell.suggest` | `{word}` | `{suggestions: [string]}`: up to five replacement words for word, best match first |
| `spell.addWord` | `{word}` | `{}`; adds word to the user's personal dictionary, so it is never flagged again. Fails with invalid params for an empty word |
| `fake.inject` | `{conversationId}` | `Message`; only in the test build |

## Events

Events are JSON-RPC notifications: `{"jsonrpc":"2.0","method":"<event>","params":<data>}`.

| Event | Data |
| --- | --- |
| `account.updated` | `Account` with the same added `attachmentLimit` as `accounts.list` (see above), so a reconnect's own update never leaves the composer's hint stale; `status` is `connecting`, `connected`, `needs-auth`, `error` or `offline` |
| `account.removed` | `{accountId}` |
| `auth.step` | `{accountId, kind, qr, hint, passwordHint}`: `kind` is `qr` (a base64 PNG to scan; reply with a `phone` to sign in by code instead), `code`, `password` or `linkcode` (WhatsApp's 8-character code, in `hint`, to type on the phone after submitting a `phone` step; no answer needed, it waits for the phone to confirm it). `passwordHint` is set only for a Telegram `password` step whose account has a two-step verification hint to show; omitted otherwise |
| `conversation.updated` | `Conversation` |
| `message.added` | `Message` |
| `message.updated` | `Message`; also sent when the service reports a message edited, or its reactions changed |
| `message.removed` | `{conversationId, messageId}`; sent when the service reports a message deleted |
| `unread.changed` | `{total, byService}`; `byService` is `{whatsapp: N, telegram: N, …}`, a service omitted meaning zero |
| `typing` | `{conversationId, name, active}` |
| `notification.clicked` | `{conversationId}`: the user clicked a desktop notification; the UI opens that conversation |
| `scheduledMessage.added` | `ScheduledMessage`; a message was queued, through `messages.schedule` |
| `scheduledMessage.updated` | `ScheduledMessage`; a queued message's text or send time changed, through `messages.editScheduled` |
| `scheduledMessage.removed` | `{conversationId, scheduledId}`; a queued message is no longer pending - cancelled, sent now, or just claimed because its own time came due. The send itself, if any, is reported separately through `message.added` and `message.updated`, not folded into this event |
| `notification.sound` | `{conversationId, service, hasCustomSound}`: sent exactly when a desktop notification is also shown for an arriving message (so never for a muted, missed or already-read one), carrying no sender name, text or file path. The UI decides from this, and its own settings, whether and what to play (see `ui/lib/NotificationSound.js`), then calls `sounds.fetch` for the actual file |

A `Message` may carry `media`: `{kind, …}` where `kind` is `link` (with `url`, restricted to the `http`, `https`, `mailto` and `tg` schemes and omitted otherwise, `siteName`, `title`, `description`), `photo`, `video`, `file`, `voice` (a voice note: WhatsApp's push-to-talk audio, Telegram's voice message), `audio` (an ordinary audio message: WhatsApp's AudioMessage without its PTT flag, Telegram's audio document without its voice flag - played through the same in-window player a `voice` note gets, shown with its own `fileName` and `duration` instead of a voice note's fixed label), `sticker` or `poll`. `thumb` is a small base64 preview sent with the message (JPEG, except for a sticker, which carries whatever format its service's own thumbnail used). `duration` (seconds) is always set on a `voice`, `audio` or `video` media. `animated` is `true` only for a `video` the sending service itself marks as a silent, looping "GIF" (WhatsApp's `gifPlayback`, Telegram's animated document attribute), omitted otherwise; the UI autoplays it muted and looping instead of waiting for a click. A `sticker` carries `emoji`, its associated emoji, shown when there is neither a `thumb` nor a downloaded image to draw: a Lottie or video sticker this UI never tries to decode, so `fileName` is left unset and `media.fetch` has nothing to download. A `poll` carries `poll`: `{question, options, multipleChoice, quiz, closed, totalVoters}`, where `options` is `[{id, text, votes, chosen, correct}]`; `chosen` is the signed-in user's own pick, `correct` is set only for a quiz and only once the user has voted or the poll closed, and there is nothing to `media.fetch`. `edited` is `true` once the service reports the message changed since it was first sent. A `Message` may also carry `replyTo`: `{remoteId, senderName, text}`, the message it answers, with `senderName` and `text` (a short excerpt) filled in once the quoted message is known locally. `reactions` is `[{emoji, count, mine}]`, omitted when the message has none; a custom-emoji reaction Telegram sends is left out rather than shown as a misleading placeholder. `mentions` is `[{userId, name, offset, length}]`, omitted when the message mentions no one; `mentionsMe` is `true` when one of them names the signed-in account, so the UI can highlight the message. `formatting` is `[{kind, start, end, url}]`, omitted when the message carries no rich-text formatting: `kind` is `link` (with `url`, restricted to the `http`, `https`, `mailto` and `tg` schemes), `bold`, `italic`, `underline`, `strike`, `code`, `pre` or `spoiler`; `start` and `end` are UTF-16 code units, the same convention a mention's `offset`/`length` uses. Set only by a connector (Telegram's own formatting entities today; WhatsApp's `*bold*`-style markers are not yet mapped), never by the composer. A failed outgoing message may carry `retryAt` (Unix milliseconds): the helper's own next automatic retry attempt, while one is scheduled; omitted once automatic retries have stopped (the failure was permanent, or they have run for as long as they will), leaving it for `messages.retry`. A received message's own `text` is capped at 64 KiB: a sender fully controls it, and the helper cuts anything longer on a valid UTF-8 boundary and appends a fixed `"[message truncated]"` notice, rather than storing or forwarding it unbounded (see `domain.MaxIncomingTextLength` and `docs/decisions.md`); outgoing text sent through `messages.send` keeps its own, much smaller limit (4096 characters).

## Errors

| Code | Meaning |
| --- | --- |
| `-32602` | Invalid params or input. The message says what to fix and is safe to show. |
| `-32601` | Unknown method, for example `fake.inject` outside the test build. |
| `-32001` | The account, contact, conversation or message does not exist. |

The shapes of `Account`, `Contact`, `Conversation` and `Message` are the JSON fields in [backend/internal/domain/domain.go](../backend/internal/domain/domain.go).

Adding or changing a method updates `server/methods.go`, its test and this file in the same change. Bump `server.Protocol` when an older UI would break; never break an existing method's params or result shape, add an optional field or a new method instead.
